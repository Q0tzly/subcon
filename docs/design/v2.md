# subcon v2: ジョブとして発行する

## 目的

- 上位エージェントが作業票を**ジョブとして発行**し、結果（パッチ＋報告）を受け取って検収する。GitHub Actions に近い使い心地
- 上位エージェントが使いやすいこと: 出力は機械可読、手順は少なく、失敗の理由が明確
- 実行場所（ランナー）を差し替えられること: まずローカル、次にコンテナ、いずれ Mac mini などのリモート

## v1 の問題

| 問題 | v2 での扱い |
| --- | --- |
| Flash が上位の作業ツリーを直接いじる。作業中は上位が何もできない | ジョブごとに専用の worktree で実行し、パッチで返す |
| 作業ツリーがクリーンでないと実行できない | ジョブは発行時の `HEAD` から始まる。未コミット分は含まれない（警告を出す） |
| 同期実行のみ。独立した票も 1 枚ずつ待つ | `submit` で非同期に発行、`wait` で待つ。複数並行可 |
| 出力が人間向けと JSON の混在 | stdout は JSON のみ、人間向けログは stderr |
| サンドボックス外実行を止められない | ランナー契約を切り、コンテナランナーで隔離する（フェーズ 2） |
| ルールの場所をエージェントが知っている必要がある | `subcon guide` で表示する |

## 用語

- **票 (ticket)**: `docs/delegation.md` の書式の Markdown 1 枚
- **ジョブ (job)**: 票 1 枚を 1 回実行したもの。ID を持ち、状態とパッチを保存する
- **ランナー (runner)**: ジョブの作業ディレクトリで agy を動かす実行場所

## コマンド

すべて git リポジトリ内で実行する（`guide` `trailer` を除く）。
stdout には JSON だけを出す。人間向けの進捗は stderr。

| コマンド | 動作 | stdout |
| --- | --- | --- |
| `subcon new <feature>/<NN-name>` | `docs/design/<feature>/<NN-name>.md` を雛形から作る。既にあればエラー | `{"path": "..."}` |
| `subcon submit [--runner R] [--model M] [--timeout T] <ticket>...` | 票ごとにジョブを作り、バックグラウンドで実行開始 | ジョブ ID の配列 |
| `subcon wait <id>...` | 全ジョブの終了を待つ | 各ジョブの結果（下記）の配列 |
| `subcon run [opts] <ticket>` | `submit` + `wait` | 結果 1 件 |
| `subcon list [--all]` | このリポジトリのジョブ一覧（`--all` で全リポジトリ） | `{id, ticket, state, status}` の配列 |
| `subcon show <id>` | 結果を表示 | 結果 1 件 |
| `subcon diff <id>` | パッチ本文を表示 | パッチ（JSON ではない。例外） |
| `subcon apply <id>` | パッチを今の作業ツリーに `git apply --3way` で当てる。コミットはしない | `{"id", "applied": true}` |
| `subcon discard <id>...` | ジョブのディレクトリと worktree を消す | `{"discarded": [...]}` |
| `subcon guide` | `docs/delegation.md` を表示 | Markdown（例外） |
| `subcon trailer [--model M]` | `Co-Authored-By` 行 | テキスト（例外） |

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功。`wait` / `run` では全ジョブが `status: done` かつ `checks.ok: true` |
| 1 | 使い方の誤り・前提不足（agy や jq が無い、票が無い等） |
| 2 | いずれかのジョブで Flash が `partial` / `blocked` を申告 |
| 3 | いずれかのジョブでチェック違反（コミットした・範囲外を変更） |
| 4 | いずれかのジョブが異常終了（agy の失敗・タイムアウト） |

複数該当するときは大きい方。

## ジョブ

### 保存場所

`${SUBCON_STATE:-${XDG_STATE_HOME:-$HOME/.local/state}/subcon}/jobs/<id>/`

| ファイル | 内容 |
| --- | --- |
| `meta.json` | `{id, repo, ticket, base, runner, model, created_at}`。`repo` はリポジトリのトップの絶対パス、`ticket` はそこからの相対パス |
| `ticket.md` | 発行時点の票のコピー |
| `state` | `queued` / `running` / `finished` / `failed` の 1 語 |
| `work/` | 実行用 worktree（`git worktree add --detach work <base>`）。終了後に削除 |
| `agy.json` | agy の生出力 |
| `patch.diff` | `base` からの変更（未追跡ファイル含む、バイナリ対応） |
| `result.json` | 結果（下記） |
| `log` | ランナーの stderr |

### ID

`<YYYYmmdd-HHMMSS>-<票のファイル名から .md を除いたもの>-<4 桁の乱数 hex>`

### 結果 (`result.json`)

```json
{
  "id": "20261110-180000-01-new-a1b2",
  "ticket": "docs/design/v2/01-new.md",
  "state": "finished",
  "status": "done",
  "checks": {
    "ok": true,
    "committed": false,
    "outside_files": [],
    "files_changed": ["bin/subcon"]
  },
  "report": { "...": "Flash の structured_output そのまま" },
  "patch": "/abs/path/to/patch.diff",
  "diffstat": "1 file changed, 20 insertions(+)",
  "error": null
}
```

- `status`: Flash の申告（`done` / `partial` / `blocked`）。agy が失敗したら `null`
- `checks.committed`: worktree の `HEAD` が `base` から動いた
- `checks.outside_files`: 票の `## Files` に無い変更ファイル
- `checks.files_changed`: 実際に変更されたファイル（Flash の申告ではなく git から求める）
- `error`: `state: failed` のときの理由（文字列）

### 流れ

1. `submit`: 票を検証（`## Files` があること）→ ジョブディレクトリ作成 → `meta.json` / `ticket.md` / `state=queued` → ランナーをバックグラウンド起動（`nohup`、親が終わっても続く）→ ID を返す
2. 作業ツリーに未コミットの変更があれば stderr に警告（ジョブには含まれない）
3. ランナー（下記）が `work/` で agy を実行
4. 後処理（ランナー共通、`lib/` 側）: `work/` で `git add -A` → `git diff --cached --binary <base>` を `patch.diff` に → チェック → `result.json` → `state=finished` → worktree 削除（`git worktree remove --force`）
5. コミットされていた場合も、`base` からの差分としてパッチに含める（`git diff --cached --binary <base>` は worktree の `HEAD` によらない）

## ランナー契約

`runners/<name>` に置く実行ファイル。引数はジョブディレクトリ 1 つ。

- 前提: `work/` は準備済み。`meta.json` と `ticket.md` がある
- 責務: `work/` をカレントにして agy を実行し、生出力を `agy.json` に書く
- 終了コード: agy が成功すれば 0。それ以外は非 0（後処理で `state=failed`）
- プロンプト・スキーマ・権限設定は `lib/` が用意したものを使う（ランナーごとに変えない）。環境変数 `SUBCON_PROMPT_FILE` `SUBCON_SCHEMA` `SUBCON_SETTINGS` `SUBCON_MODEL` `SUBCON_TIMEOUT` で渡す

### local（フェーズ 1）

v1 と同じ agy 呼び出しを `work/` で行う。隔離は worktree 単位までで、サンドボックスの限界は v1 と同じ。

### container（フェーズ 2、この doc では契約のみ）

`work/` をマウントしたコンテナで agy を実行する。中は使い捨てなので権限は全許可でよい。
前提確認が要る: agy が Linux で動くか、認証情報の渡し方。

### remote（フェーズ 3、構想のみ）

ssh 先（Mac mini など）で同じ契約を満たす。`work/` を git bundle で送り、パッチで返す。

## 上位エージェント向けの使い方

`subcon guide` の先頭に、上位が最短で使える手順を置く。

```sh
subcon new myfeat/01-parser                    # 票の雛形を作って書く
git commit -m "add: ticket for parser"         # ジョブは HEAD から始まる
subcon submit docs/design/myfeat/01-*.md docs/design/myfeat/02-*.md   # 独立した票は並行に
subcon wait <id> <id>                          # 結果 JSON で判断
subcon diff <id>                               # 読む
subcon apply <id> && <Acceptance を自分で実行>
git commit                                     # trailer は subcon trailer
subcon discard <id>
```

## ファイル構成

```
bin/subcon            # サブコマンドの振り分けだけ
lib/common.sh         # パス・JSON 出力・エラー
lib/ticket.sh         # 票の解析（## Files の抽出）・雛形
lib/job.sh            # ジョブの作成・状態・後処理・チェック
lib/prompt.md         # Flash へのプロンプト前文
runners/local
schema/result.schema.json   # Flash の報告スキーマ（v1 から変更なし）
templates/ticket.md
tests/run.sh          # テスト一式（素の bash、外部依存なし）
tests/fake-agy        # agy の代わり。挙動を環境変数で切り替える
```

## テスト

- `tests/run.sh` が全テストを実行し、失敗があれば非 0 で終わる
- 本物の agy は使わない。`tests/fake-agy` を `PATH` の先頭に置く
  - `FAKE_AGY_MODE=ok`: 票の `## Files` の最初のファイルに 1 行追記し、done を返す
  - `FAKE_AGY_MODE=outside`: 範囲外のファイルを作る
  - `FAKE_AGY_MODE=commit`: コミットする
  - `FAKE_AGY_MODE=fail`: 非 0 で終わる
  - `FAKE_AGY_MODE=sleep`: 数秒待ってから ok と同じ動作（並行実行の確認用）
  - `models` サブコマンドには固定の一覧を返す
- 各テストは一時ディレクトリに git リポジトリと `SUBCON_STATE` を作り、終わったら消す

## v1 からの互換

- `subcon run` は残すが、出力が JSON（結果 1 件）に変わる。v1 の人間向け出力は stderr に移る
- `.git/subcon/` へのログは廃止（ジョブディレクトリに移る）
- 作業ツリーを直接変更しなくなるので、`run` の後は `apply` が要る

## やらないこと（v2 では）

- ジョブの自動リトライ、自動 apply、自動コミット
- ジョブの優先度・同時実行数の制御（必要になったら `SUBCON_MAX_JOBS`）
- container / remote ランナーの実装

## 未決事項

- `submit` のバックグラウンド実行を `nohup` で十分とするか。上位エージェントのセッションが終わってもジョブは続く想定
- `wait` にタイムアウトを持たせるか（上位側のツール呼び出しの時間上限に当たる）
