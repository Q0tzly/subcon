# subcon v2: ジョブとして発行する

## 目的

- 上位エージェントが作業票を**ジョブとして発行**し、結果（パッチ＋報告）を受け取って検収する。GitHub Actions に近い使い心地
- 上位エージェントが使いやすいこと: 出力は機械可読、手順は少なく、失敗の理由が明確
- 実行場所（ランナー）を差し替えられること: まずローカル、次にコンテナ、いずれ Mac mini などのリモート

## v1 の問題

| 問題 | v2 での扱い |
| --- | --- |
| Flash が上位の作業ツリーを直接いじる。作業中は上位が何もできない | ジョブごとに専用の worktree で実行し、パッチで返す |
| 作業ツリーがクリーンでないと実行できない | ジョブは発行時の `HEAD` から始まる。未コミット分は含まれない（警告を出す） |
| 同期実行のみ。独立した票も 1 枚ずつ待つ | `submit` で非同期に発行、`wait` で待つ。複数並行可 |
| 出力が人間向けと JSON の混在 | stdout は JSON のみ、人間向けログは stderr |
| サンドボックス外実行を止められない | ランナー契約を切り、コンテナランナーで隔離する（フェーズ 2） |
| ルールの場所をエージェントが知っている必要がある | `subcon guide` で表示する |

## 用語

- **票 (ticket)**: `docs/delegation.md` の書式の Markdown 1 枚
- **ジョブ (job)**: 票 1 枚を 1 回実行したもの。ID を持ち、状態とパッチを保存する
- **ランナー (runner)**: ジョブの作業ディレクトリで agy を動かす実行場所

## 票の検証

`submit` は票ごとに次を確かめる。1 枚でも満たさなければ**どのジョブも作らず**終了コード 1。

- 票のファイルがリポジトリ内にあり、`HEAD` にコミット済みで、作業ツリーとの差分が無い（Flash は `HEAD` から実装するので、票も `HEAD` と一致している必要がある）
- `## Files` に 1 件以上のパスがある
- 各パスがリポジトリのトップからの相対パスで、`/` で始まらず、`.` や `..` の要素を含まず、`*` `?` `[` を含まない
- 照合は、この書式のパスと git が出すパス（正規化済み）との完全一致で行う

## コマンド

すべて git リポジトリ内で実行する（`guide` `trailer` と、`stats --all` を除く）。
stdout には JSON だけを出す（`diff` `guide` `trailer` と、`stats --text` を除く）。人間向けの進捗とエラーは stderr。

agy が要るコマンド（`submit` `run` `resume` `trailer`）は、実行前に agy を解決する: PATH に無ければ `$HOME/.local/bin/agy` を探し、どちらにも無ければジョブを作らず終了コード 1（`agy not found`）。agy が要らないコマンドにはこの確認を入れない。

| コマンド | 動作 | stdout |
| --- | --- | --- |
| `subcon new <feature>/<NN-name>` | `docs/design/<feature>/<NN-name>.md` を雛形から作る。既にあればエラー | `{"path": "..."}` |
| `subcon submit [--runner R] [--model M] [--timeout T] <ticket>...` | 全票を検証してから、票ごとにジョブを作りバックグラウンドで実行開始 | `[{"ticket", "id", "error"}]`（起動に失敗した票は `id: null` と理由） |
| `subcon wait [--timeout SEC] <id>...` | 全ジョブの終了を待つ | 各ジョブの結果（下記）の配列 |
| `subcon run [submit の opts] <ticket>` | `submit` + `wait`（票 1 枚） | 結果 1 件 |
| `subcon resume [--timeout T] <id>` | 失敗したジョブを、agy の会話を引き継いで新しいジョブとして再開する | `[{"ticket", "id", "resume_of", "error"}]` |
| `subcon show <id>` | 結果を表示。実行中なら `state` だけ埋まった結果 | 結果 1 件 |
| `subcon list [--all]` | このリポジトリのジョブ一覧。`--all` で全リポジトリ（表示のみ） | `[{id, repo, ticket, state, status, created_at}]`（新しい順） |
| `subcon diff <id>` | `patch.diff` をそのまま表示 | パッチ |
| `subcon apply <id>` | パッチを今の作業ツリーに当てる。コミットはしない | `{"id", "applied": true}` |
| `subcon discard <id>...` | ジョブを消す | `{"discarded": [...]}` |
| `subcon stats [--all] [--since <N>d\|<N>h] [--text]` | `history.jsonl` の集計（下記「使用統計」節） | 集計 JSON（`--text` では人間向けの表） |
| `subcon guide` | `docs/delegation.md` を表示 | Markdown |
| `subcon trailer [--model M]` | `Co-Authored-By` 行 | テキスト |

### オプション

- `--runner R`: `runners/` にある実行ファイル名。既定 `local`。無ければ終了コード 1
- `--model M`: agy のモデル ID。既定は `SUBCON_MODEL`、未設定なら `gemini-3.8-flash-medium`
- `--timeout T`（submit / run）: agy の `--print-timeout` に渡す。既定 `30m`。これによりランナーは必ず終わる
- `--timeout SEC`（wait）: 秒。既定 0（無期限）。期限が来たら、その時点の結果（未終了は `state: queued/running`）を出して終了コード 5。ジョブは止めない
- 上位エージェントのツール呼び出しには時間上限があるので、`subcon guide` では `wait --timeout 540` を繰り返す使い方を勧める

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 成功。`wait` / `run` では全ジョブが `status: done` かつ `checks.ok: true` |
| 1 | 使い方の誤り・前提不足（agy や jq が無い、票の検証失敗、未知の ID、パッチが当たらない等） |
| 2 | いずれかのジョブで Flash が `partial` / `blocked` を申告 |
| 3 | いずれかのジョブでチェック違反（コミットした・範囲外を変更） |
| 4 | いずれかのジョブが `state: failed`（agy の失敗・タイムアウト・ランナーの消失・起動失敗） |
| 5 | `wait` のタイムアウト |

複数該当するときは大きい方。

## ジョブ

### 保存場所

`${SUBCON_STATE:-${XDG_STATE_HOME:-$HOME/.local/state}/subcon}/jobs/<id>/`

| ファイル | 内容 |
| --- | --- |
| `meta.json` | `{id, repo, ticket, base, runner, model, timeout, created_at}`。`repo` はリポジトリのトップの絶対パス、`ticket` はそこからの相対パス、`created_at` は ISO 8601。`resume` で作ったジョブだけ `resume_of` と `conversation` が加わる |
| `ticket.md` | `HEAD` の票（`git show HEAD:<ticket>`） |
| `state` | `queued` / `running` / `finished` / `failed` の 1 語 |
| `pid` | ランナーを包むプロセスの PID |
| `work/` | 一時領域。実行用 worktree（`git worktree add --detach`）。終了時に必ず削除 |
| `agy.json` | agy の最終結果（`--output-format json` と同じ形。無いこともある） |
| `agy.stream` | local ランナーが取る agy の `stream-json` 出力。`agy.json` の元 |
| `patch.diff` | `base` からの変更（未追跡ファイル含む、バイナリ対応）。作れなかったら無い |
| `result.json` | 結果（下記）。`finished` / `failed` のときに必ずある |
| `log` | ランナーの stderr |

`state` `result.json` `meta.json` は一時ファイルに書いてから `mv` で置き換える（読み途中の破損を避ける）。

### ID

`<YYYYmmdd-HHMMSS>-<票のファイル名から .md を除いたもの>-<4 桁の乱数 hex>`。
ジョブディレクトリは `mkdir`（`-p` なし）で排他的に作り、既にあれば ID を作り直す（5 回まで。駄目なら起動失敗）。

### 結果 (`result.json`)

```json
{
  "id": "20261110-180000-01-new-a1b2",
  "repo": "/abs/path/to/repo",
  "ticket": "docs/design/v2/01-new.md",
  "state": "finished",
  "status": "done",
  "checks": {
    "ok": true,
    "committed": false,
    "outside_files": [],
    "files_changed": ["lib/ticket.sh"]
  },
  "report": { "...": "Flash の structured_output そのまま" },
  "patch": "/abs/path/to/patch.diff",
  "diffstat": "1 file changed, 20 insertions(+)",
  "error": null,
  "agy_error": null,
  "conversation": "agy の conversation_id（無ければ null）"
}
```

- `state`: `finished` は agy が正常に終わった。`failed` はそれ以外
- `status`: Flash の申告（`done` / `partial` / `blocked`）。申告が無ければ `null`
- `checks`: パッチが作れたときだけ埋める。作れなければ `null`
  - `committed`: worktree の `HEAD` が `base` から動いた
  - `outside_files`: 票の `## Files` に無い変更ファイル
  - `files_changed`: 実際に変更されたファイル（Flash の申告ではなく git から求める）
  - `ok`: `committed` が false かつ `outside_files` が空
- `report`: agy 出力の `structured_output`。無ければ `null`
- `patch` / `diffstat`: パッチが無ければ `null`。変更ゼロなら `patch` はあり `diffstat` は空文字
- `error`: `failed` のときの理由（文字列）。それ以外は `null`
- `agy_error`: agy 出力の `error`（あれば）。`conversation`: agy 出力の `conversation_id`。失敗時も agy が書いていれば残る（`resume` の材料）
- 実行中（`show` / `wait` のタイムアウト時）は `id` `repo` `ticket` `state` だけ埋め、他は `null`

### 流れ

`submit`（前景、同期）:

1. 全票を検証（上記）。駄目なら何も作らず終了コード 1
2. 作業ツリーに未コミットの変更があれば stderr に警告（ジョブには含まれない）
3. 票ごとに: ジョブディレクトリを排他作成 → `meta.json` `ticket.md` → `state=queued` → `work/` に worktree 作成 → ランナーを `nohup … &` で起動し `pid` を書く
4. 3 のどこかで失敗したら、その票の `work/` とジョブディレクトリを消し、stdout の要素に `id: null` と `error` を入れて次の票へ。終了コードは 1 件でも失敗があれば 4

バックグラウンド（`lib/job.sh` の実行関数がランナーを包む）:

1. `trap` で、どの終わり方でも後処理（下記）が走るようにする
2. `state=running` → `runners/<R> <ジョブディレクトリ>` を実行、stderr を `log` へ
3. 後処理:
   1. `work/` があれば: `git -C work add -A` → `git -C work diff --cached --binary <base>` を `patch.diff` へ（`HEAD` が動いていても `base` からの差分になる）→ チェック
   2. `result.json` を書く。ランナーが 0 で終わり `agy.json` が読めれば `finished`、それ以外は `failed`
   3. `state` を更新 → `git worktree remove --force work`（失敗したら `rm -rf work` と `git worktree prune`）

ランナーの消失（kill -9 など、`trap` も走らない場合）:

- `wait` / `show` / `list` は、`state` が `queued` / `running` なのに `pid` のプロセスが居なければ、その場で `failed`（`error: "runner died"`）として `result.json` を書き、worktree を片付ける

## ランナー契約

`runners/<name>` に置く実行ファイル。引数はジョブディレクトリ 1 つ。

- 前提: `work/` は準備済み。`meta.json` と `ticket.md` がある
- 責務: `work/` をカレントにして agy を実行し、最終結果を `agy.json` に書く（kill などで結果が無くても、会話 ID が分かれば `{status: "ERROR", conversation_id, error}` を書く）。ほかに書くのはランナー固有のログだけ
- 終了コード: agy が成功すれば 0。それ以外は非 0
- プロンプト・スキーマ・権限設定は `lib/` が用意したものを使う（ランナーごとに変えない）。環境変数 `SUBCON_PROMPT_FILE`（前文と票を連結済みのファイル）`SUBCON_SCHEMA` `SUBCON_SETTINGS` `SUBCON_MODEL` `SUBCON_TIMEOUT` で渡す

### local（フェーズ 1）

v1 と同じ agy 呼び出しを `work/` で行う。隔離は worktree 単位までで、サンドボックスの限界は v1 と同じ。

### container（フェーズ 2）

`work/` をマウントしたコンテナで agy を実行する。中は使い捨てなので権限は全許可でよい。
詳細設計は `docs/design/container-runner.md`（前提確認済み: agy は Linux で動作し、認証情報は `$HOME/.gemini` のマウントで渡せる）。

### remote（フェーズ 3、構想のみ）

ssh 先（Mac mini など）で同じ契約を満たす。`work/` を git bundle で送り、パッチで返す。

## apply

1. ジョブの `meta.json` の `repo` が今のリポジトリのトップと一致しなければ終了コード 1
2. `state` が `finished` でなく、`patch.diff` も無ければ終了コード 1
3. `git apply --check patch.diff` が失敗したら、何も変えずに終了コード 1（3-way は使わない。競合マーカーを残さないため）
4. `git apply patch.diff`（index は触らない）

## discard

- 全 ID が存在することを先に確かめ、1 つでも無ければ何も消さず終了コード 1
- 実行中のジョブは、`pid` に SIGTERM を送り、最大 5 秒待ってから消す
- `work/` が残っていれば worktree を片付けてから、ジョブディレクトリを消す

## 上位エージェント向けの使い方

`subcon guide` の先頭に、上位が最短で使える手順を置く。

```sh
subcon new myfeat/01-parser                    # 票の雛形を作って書く
git add docs/design/myfeat && git commit -m "add: ticket for parser"   # 票はコミット必須
subcon submit docs/design/myfeat/01-*.md docs/design/myfeat/02-*.md   # 独立した票は並行に
subcon wait --timeout 540 <id> <id>            # 5 なら繰り返す。結果 JSON で判断
subcon diff <id>                               # 読む
subcon apply <id> && <Acceptance を自分で実行>
git commit                                     # trailer は subcon trailer
subcon discard <id>
```

## ファイル構成

```
bin/subcon            # サブコマンドの振り分けだけ（全サブコマンド分を 02 で用意）
lib/common.sh         # パス・JSON 出力・エラー・アトミック書き込み
lib/ticket.sh         # 票の解析・検証・雛形
lib/job.sh            # ジョブの作成・実行・後処理・チェック・照会
lib/query.sh          # wait / show / run
lib/manage.sh         # list / diff / apply / discard
lib/history.sh        # history.jsonl への記録
lib/stats.sh          # subcon stats
lib/prompt.md         # Flash へのプロンプト前文
lib/resume-prompt.md  # resume のときのプロンプト
runners/local
schema/result.schema.json   # Flash の報告スキーマ（v1 から変更なし）
templates/ticket.md
tests/run.sh          # テスト一式（素の bash、外部依存なし）
tests/fake-agy        # agy の代わり。挙動を環境変数で切り替える
```

## テスト

- `tests/run.sh [グループ...]` がテストを実行し、失敗があれば非 0 で終わる。引数なしで全グループ
- 本物の agy は使わない。`tests/fake-agy` を `PATH` の先頭に置く
  - `FAKE_AGY_MODE=ok`: 票の `## Files` の最初のファイルに 1 行追記し、done を返す
  - `FAKE_AGY_MODE=outside`: 範囲外のファイルを作る
  - `FAKE_AGY_MODE=commit`: コミットする
  - `FAKE_AGY_MODE=partial`: 変更なしで partial を返す
  - `FAKE_AGY_MODE=fail`: 非 0 で終わる
  - `FAKE_AGY_MODE=sleep`: `FAKE_AGY_SLEEP` 秒待ってから ok と同じ動作（並行実行・タイムアウト・kill の確認用）
  - `models` サブコマンドには固定の一覧を返す
- 各テストは一時ディレクトリに git リポジトリと `SUBCON_STATE` を作り、終わったら消す

## v1 からの互換

- `subcon run` は残すが、出力が JSON（結果 1 件）に変わる。v1 の人間向け出力は stderr に移る
- `.git/subcon/` へのログは廃止（ジョブディレクトリに移る）
- 作業ツリーを直接変更しなくなるので、`run` の後は `apply` が要る
- 作業ツリーがクリーンである必要はなくなるが、票はコミット済みである必要がある

## 中断からの再開（v2.1）

票 04 の委任がネットワークエラーで 13 分目に落ち、`agy --conversation <ID>` で続きから再開できた（5 分で完了）。これをコマンドにした。

前提（確認済み）:
- agy はエラー終了時も JSON 出力に `conversation_id` を書く（`status: "ERROR"`, `error` あり）
- 会話は `~/.gemini/antigravity-cli/conversations/<ID>.db` に保存され、途中で kill しても残る
- `--conversation <ID>` と `-p` を併用すれば、前回の文脈のまま続きを指示できる

`subcon resume [--timeout T] <id>`:
- 対象: `state: failed` で `result.json` の `conversation` があるジョブ。このリポジトリのジョブに限る。満たさなければ終了コード 1
- 新しいジョブを作る。`meta.json` に `resume_of`（元の id）と `conversation` を足す。`base`・ランナー・モデル・票は元と同じ、`--timeout` は省略すれば元と同じ
- worktree を作ったら、元の `patch.diff` を `git apply --binary` で当ててから（途中までの作業を引き継ぐ）ランナーを起動する。当たらなければ起動失敗（終了コード 4）
- プロンプトは `lib/resume-prompt.md`（「中断された。作業ツリーを確認して続けろ」）だけ。票と規則は会話が覚えている。ランナーには `SUBCON_CONVERSATION` を渡し、local は `--conversation` を付ける
- 再開したジョブがまた失敗したら、それをさらに再開できる（`resume_of` は直前のジョブ）。履歴にも `resume_of` が残る
- 元のジョブは残る。再開が成功したら `discard` してよい

local ランナーは `--output-format stream-json` で動かし、最初の `init` イベントの `conversation_id` を拾う。agy が結果を書く前に SIGKILL されても、`agy.json` に `error: "agy exited without a result"` と会話 ID が残り、再開できる。`init` の前に落ちた場合だけ `conversation` が無く、票を `submit` し直す。

### 実機での検証（2026-11-10、agy 1.5.4、`gemini-3.8-flash-medium`）

使い捨てのリポジトリで、「`src/f01.txt` 〜 `f10.txt` を 1 つずつ作る」票を使った。fake-agy ではなく本物の agy。

| 試したこと | 結果 |
| --- | --- |
| `--timeout 25s` で打ち切る | 2 ファイル作った時点で `failed`（`runner exited with 3`）。`agy_error` は `print timeout after 25s with the turn still in progress; the response is partial`。`conversation` が取れ、途中の 2 ファイルは `patch.diff` に残る |
| `resume` で再開 | `finished` / `done`、10 ファイル・`checks.ok: true`。`conversation` は元と同じで、agy の `num_turns` は 2（会話の続き）。約 205 秒、トークン合計は約 21.6 万。再開プロンプトは短い 1 文だけで足りた |
| 再開したジョブを `apply` | 当たる。同じパッチをもう一度当てると `patch does not apply cleanly`（終了コード 1） |
| agy を SIGKILL（`--output-format json` のとき） | `agy.json` が空で `conversation` が `null`、`resume` は終了コード 1 で拒否。会話 DB（`~/.gemini/antigravity-cli/conversations/<ID>.db`）は残っていた |
| `--output-format stream-json` | 最初の `init` イベントに `conversation_id` がある。最終の `result` イベントは `json` 出力と同じ形で、`--json-schema` を付けても `structured_output` が入る |
| local ランナーを `stream-json` にして SIGKILL → `resume` | `agy.json` に `{status: "ERROR", conversation_id, error: "agy exited without a result"}` が残り、再開して `finished` / `done`（10 ファイル・チェック OK） |

未検証:
- `init` イベントが出る前に落ちた場合（`conversation` が `null` のまま。テストは fake-agy の `error_noconv` のみ）
- 別マシンのランナーでの再開（会話 DB は agy を動かしたマシンに残る。remote ランナーでは同じマシンで再開する必要がある）

根本対策はサーバー側のランナー（フェーズ 2・3）で、上位のマシンのネットや電源に左右されないようにすること。再開はそれでも残る失敗（agy 側のエラー・クォータ）への備え。

## 使用統計（v2.2、実装済み）

票 10（履歴の記録）・票 11（`subcon stats`）で実装済み。

rtk の `rtk gain` のように、委任がどれだけ使われ、どれだけ役に立ったかを見られるようにする。
「Flash に渡す価値があったか」を測るのが目的。

記録（`discard` でジョブを消しても残す）:
- `job_finalize` の最後に `$(state_root)/history.jsonl` へ 1 行追記する
  - `{id, repo, ticket, model, runner, created_at, finished_at, duration_s, state, status, checks_ok, files_changed, insertions, deletions, tokens: {input, output, total, cache_read, thinking}, resume_of}`
  - `duration_s` と `tokens` は agy 出力の `duration_seconds` と `usage` から取る（無ければ `null`）
- `apply` の成功時に `{id, event: "applied", at}` を追記する。「当てたか」で、使い物になった割合を測る

表示:
- `subcon stats [--all] [--since 7d]`: このリポジトリ（`--all` で全体）の集計を JSON で出す
  - ジョブ数、`state` / `status` 別の件数、成功率（`done` かつ `checks_ok`）、apply 率
  - 所要時間の合計と中央値、トークンの合計
  - モデル別の内訳
- `--text` で人間向けの表（`rtk gain` 風）

## やらないこと（v2 では）

- ジョブの自動リトライ、自動 apply、自動コミット
- ジョブの優先度・同時実行数の制御（必要になったら `SUBCON_MAX_JOBS`）
- `--all` で他リポジトリのジョブを `apply` すること（表示のみ）
